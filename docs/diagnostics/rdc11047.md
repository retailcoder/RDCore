# RDC11047: Object assigned with Let to an object property

**Severity:** Warning &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `ObjectLetToObjectPropertyAnalyzer`

A `Let` assignment gives an object to a property whose value parameter is a class or `Object`.

RD-VBA passes the property the object itself, as MS-VBA does, the way a `Set` would pass it. An object of another class than the parameter's is
run-time error 13.
[**MS-VBAL §5.5.1.1** Static semantics](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/4ef84713-33da-445b-942e-345982b3267d)
makes the `Let` a type mismatch instead, and
[**MS-VBAL §5.4.3.8** Let Statement](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/ce2a98d4-2625-4cb7-982c-5c58e568cd18)
with [**MS-VBAL §5.5.1.2.13** Let-coercion to and from a class or Object or Nothing](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/9b8fc7b4-8329-497d-b2dd-2d0fa2b7b48c)
evaluates the object as its default member's value: run-time error 424, or 91 for `Nothing`.

```vb
Dim h As New Holder       ' Property Let Picture(ByVal v As Object)
Dim p As Object
Set p = LoadPicture("logo.bmp")
h.Picture = p             ' h receives the picture object itself
```

The warning is raised where the value is declared as an object (a class, or `Object`) and the property is bound early. A `Variant` that holds an
object at run time, and a property called late, are not reported.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|The property is meant to receive the object.|`h.Picture = p`|Assign it with `Set`: declare a `Property Set` and write `Set h.Picture = p`.|
|The property is meant to receive the default member's value.|`h.Picture = p`|Name the default member, and give the property a value parameter of that type.|
