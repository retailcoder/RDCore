# RDC01009: Empty procedure

**Severity:** Information &nbsp;·&nbsp; **Family:** `RDC` (Rubberduck Core analyzers) &nbsp;·&nbsp;
**Raised by:** `EmptyProcedureAnalyzer`

A `Sub`, `Function` or `Property` procedure has no statement
([**MS-VBAL §5.3.1.6** Subroutine and Function Declarations](../specs/rd-vbal.5.3.1.6.subroutine-and-function-declarations.md),
[**§5.3.1.7** Property Declarations](../specs/rd-vbal.5.3.1.7.property-declarations.md)).

Calling it does nothing, and a function or a property getter returns the default value of its type. An empty procedure is often unfinished code, or left over.
Comments, line labels and `Dim`, `Static` and `Const` declarations are no statements: a procedure that holds only those is empty.

A `Public` member of a class module is a member of the interface of the class, which another class module can implement with `Implements`
([**MS-VBAL §5.2.4** Class Module Declarations](../specs/rd-vbal.5.2.4.class-module-declarations.md)). A class written as an interface declares its members with no
statement, so a `Public` member of a class module is not reported. A `Private` or `Friend` member of a class is, and so is a member that implements an interface or handles
an event, whatever its access.

The finding is the name of the procedure.

## How it is raised

|Situation|Example|Resolution|
|---|---|---|
|A procedure of a standard module with no statement.|`Sub Foo()`<br>`    ' ...`<br>`End Sub`|Write what it does, or remove it.|
|A `Private` or `Friend` procedure of a class module with no statement.|`Private Sub Class_Initialize()`<br>`End Sub`|Remove it, or write what it does.|
|An implementation of an interface member, or an event handler, with no statement.|`Private Sub Source_Click()`<br>`End Sub`|Write what it does. An implementation that is meant to do nothing says so in a comment.|
